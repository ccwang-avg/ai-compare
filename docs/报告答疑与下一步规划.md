# 报告答疑与下一步规划

## 一、先回答你的 3 个问题

### 1. 现在填充的数据，是否来源于网上的调研结果？

结论：**当前这版内容看起来是“基于公开信息整理后的结构化填充”，但还不能直接表述为“已经完成了严格的联网调研”。**

原因有两个：

- 数据结构里已经预留了 `sources` 和 `updatedAt`，说明方案设计上是按“可追溯调研”来做的。
- 但从页面呈现来看，来源信息没有成为核心内容的一部分，且大多数字段目前更像是基于公开认知、产品理解和二次归纳后的总结，而不是逐条证据挂载后的研究结论。

面试时更稳妥的表述建议改成：

> 当前版本的数据主要基于公开资料、官网信息和产品理解做了第一轮结构化整理，已经预留来源链接和更新时间字段。下一步会把关键判断补齐到“可追溯证据链”的版本。

不要直接说：

> 这些内容全部来自完整的线上调研。

因为如果面试官继续追问“每个判断对应哪条证据”“定价和定位更新时间是什么”，当前页面还接不住。

### 2. 如果面试时想体现竞品分析能力，这个页面应该怎么改？

当前页面更像：

- 一个“整理过的 AI 产品报告”
- 一个“有分析感的展示页”

但还不够像：

- 一个“有方法论、有判断过程、有证据支撑的竞品分析作品”

如果目标是面试里体现你的竞品分析能力，页面重点要从“展示信息”改成“展示你的分析方法和判断过程”。

建议增加 4 个层次：

#### 2.1 先把“研究任务”说清楚

在页面开头增加一个 `本次分析任务` 区块，明确：

- 研究目标：为什么分析这些产品
- 研究对象：纳入了哪些产品，排除了哪些产品
- 研究问题：想回答什么问题
- 研究口径：基于哪些公开资料、时间截至哪一天

这一步体现的是：**你不是在堆产品资料，而是在完成一个分析任务。**

#### 2.2 把“分析框架”前置展示

建议单独做一个 `分析框架` 区块，明确写出四个维度：

1. 产品定位
2. 体验设计
3. 能力边界
4. 商业化路径

每个维度都要写一句“我用什么问题来判断”，例如：

- 产品定位：它服务谁，解决什么高频任务，主战场在哪里
- 体验设计：它如何降低上手门槛，如何组织关键工作流
- 能力边界：它强在哪，弱在哪，哪些任务无法稳定完成
- 商业化路径：它靠什么收费，靠谁付费，如何承接团队或企业场景

这一步体现的是：**你有分析框架，而不是凭感觉评价产品。**

#### 2.3 把“结论”改成“判断 + 依据”

现在很多模块只有结论，没有显式依据。建议所有关键结论都升级成：

- 判断
- 依据
- 影响

例如：

- 判断：Perplexity 更像研究入口，而不是通用助手替代品
- 依据：产品首页、交互路径、引用机制、核心场景都围绕检索与信息整合展开
- 影响：它在事实核查和资料收集环节更强，但在复杂创作闭环上不占优

这一步体现的是：**你能解释为什么得出这个结论。**

#### 2.4 增加“横向洞察”，而不是只做单产品介绍

面试官更想看到你能不能总结赛道规律，而不只是介绍产品。

建议补一个 `关键洞察` 区块，沉淀 3 到 5 条跨产品判断，例如：

- 通用助手的竞争焦点，正在从模型能力转向工作流承接能力
- AI 搜索的核心价值不是“更会回答”，而是“更低成本地获得可核查信息”
- 编程 Agent 的分水岭不在会不会写代码，而在能否进入真实工程闭环
- 中文助手的差异化不只是中文输出，而是资料处理链路和低门槛体验

这一步体现的是：**你能从样本中抽象出行业判断。**

### 3. 现在的分析框架是“产品定位、体验设计、能力边界、商业化路径”，但对比矩阵和详情页没有明显体现，怎么处理？

这个判断是对的。当前项目存在明显的“框架和页面脱节”问题：

- 数据层已经有 `analysis.positioning / experience / capability / business`
- 详情页也有对应的分析段落
- 但对比矩阵展示的主要还是标签、等级、优势、风险
- 用户无法一眼看出“这个矩阵是在用哪套框架比较”

也就是说，现在是：

- **数据里有框架**
- **页面里有局部框架**
- **主对比区没有把框架显性化**

这会导致面试时出现两个问题：

- 面试官看不出你的分析方法
- 页面看起来像“信息整理”，不像“框架驱动的竞品分析”

正确处理方式不是推翻现有结构，而是把框架显性挂到页面上。

## 二、重新整理后的整体方案

### 2.1 页面目标重新定义

建议把这个项目定义成：

> 一份基于公开资料与产品体验整理的 AI 产品竞品分析报告，用统一框架对主流样本进行横向比较，并输出可解释的判断结论。

这个定义比“AI 产品对比页”更适合面试，因为它同时强调了：

- 研究对象
- 方法框架
- 横向比较
- 输出结论

### 2.2 内容结构重组

建议页面按下面顺序组织：

1. 报告概述
2. 研究范围与样本口径
3. 分析框架说明
4. 关键洞察
5. 对比矩阵
6. 重点产品详情
7. 证据来源与更新时间
8. 方法说明与局限性

这样改完后，整页叙事会从“展示产品”变成“展示分析过程和结论”。

### 2.3 对比矩阵怎么改

当前对比矩阵的主要问题不是信息少，而是**缺少框架映射**。

建议改成两层矩阵：

#### 方案 A：一级维度矩阵

矩阵列直接对应分析框架：

- 产品
- 产品定位
- 体验设计
- 能力边界
- 商业化路径
- 代表场景
- 主要优势
- 主要风险

其中前四列不要写成长段，而要写成“短句判断”。

例如：

- 产品定位：通用入口 / 研究入口 / 编程闭环 / 中文资料处理
- 体验设计：低门槛对话式 / 搜索式 / IDE 内协作式 / 文档导向式
- 能力边界：强研究弱创作 / 强编码弱通用 / 强多模态弱企业承接
- 商业化路径：个人订阅驱动 / 企业承接驱动 / 平台生态承接

#### 方案 B：二级能力矩阵

保留你现在这类等级判断，但它应该作为“能力展开层”，而不是主叙事层。

建议列：

- 多模态
- 研究检索
- 编程协作
- Agent 执行
- 企业落地
- 体验成熟度

这样就能形成：

- 一级矩阵回答“它是什么产品”
- 二级矩阵回答“它在哪些能力上强弱不同”

### 2.4 详情页怎么改

详情页现在已经有框架段落，但还缺两类信息：

#### 1. 每个维度的“判断依据”

建议在每个分析段落下补一行：

- 判断依据：官网定位 / 定价页 / 功能页 / 实际交互路径 / 来源链接

不一定要很长，但一定要让人知道结论不是空口说的。

#### 2. 每个产品的“竞品角色”

建议新增一个 `在样本中的角色` 区块，例如：

- ChatGPT：通用助手基准样本
- Perplexity：研究检索样本
- Cursor：编程 Agent 样本
- Kimi：中文资料处理样本

这会直接体现你有“样本选择逻辑”。

### 2.5 来源信息怎么改

来源不要只放在详情页底部作为附录，建议升级成两个层次：

#### 页面级说明

在首页或矩阵上方说明：

- 数据来源以官网、定价页、产品说明页为主
- 判断基于公开资料整理与通用体验观察
- 内容有时间性，需结合更新时间理解

#### 产品级来源

每个产品保留：

- 来源链接
- 更新时间
- 关键判断对应的证据点

这样你在面试里就能把“调研能力”和“结构化表达能力”连起来。

## 三、建议你在面试里重点呈现的能力点

如果目标是体现竞品分析能力，页面最应该放大的不是“我知道很多产品”，而是下面这 4 个能力：

### 1. 样本选择能力

你为什么选这几个，而不是随便列一堆产品。

建议显式写出纳入标准：

- 赛道代表性
- 用户认知度
- 产品形态差异
- 可获取公开资料
- 近一年仍在持续更新

### 2. 分析框架搭建能力

你是如何把复杂产品放进统一框架里比较的。

建议在页面明确说明：

- 为什么用“定位、体验、能力、商业化”这四维
- 为什么它们足够覆盖用户价值和产品竞争逻辑

### 3. 证据组织能力

不是只有观点，还要有依据。

建议让页面里所有重要判断都能回答：

- 这个结论从哪里来的
- 依据是官网、功能、定价还是体验路径

### 4. 输出结论能力

分析不能停留在描述。

建议补充：

- 赛道趋势判断
- 样本差异总结
- 如果我是产品经理，会重点关注哪些机会点

## 四、下一步规划

### 第一阶段：把页面从“展示页”改成“分析报告页”

目标：先解决叙事结构问题。

建议动作：

1. 新增 `研究范围与方法` 区块
2. 新增 `分析框架` 区块
3. 新增 `关键洞察` 区块
4. 重写对比矩阵字段，让四大分析维度显性化
5. 在详情页补 `样本角色` 和 `判断依据`

这一阶段完成后，面试时已经能比较完整地讲“我怎么做竞品分析”。

### 第二阶段：把“结论”补成“有证据链的结论”

目标：解决你第 1 个问题里的可信度问题。

建议动作：

1. 按产品补官网、定价页、功能页来源
2. 给关键字段补更新时间
3. 给关键判断补证据点说明
4. 区分“公开事实”与“我的分析判断”

这一阶段完成后，页面就能从“结构化整理”升级成“可追溯研究”。

### 第三阶段：增加更能体现分析深度的产出

目标：把项目从“页面好看”升级成“作品有深度”。

建议补充 3 类内容：

1. 赛道趋势结论
2. 机会点判断
3. 如果我来做这类产品，会优先打哪个场景

这类内容最能体现产品经理视角，而不只是资料整理能力。

## 五、最终建议

针对你当前这个项目，我建议你不要把它继续往“信息更全”方向堆，而要往“分析逻辑更清楚”方向改。

核心判断可以概括为三句话：

- 现在的数据结构已经具备“研究型报告”的雏形，但页面没有把这套逻辑显性表达出来。
- 如果面试要体现竞品分析能力，重点不是增加更多产品，而是把“样本选择、分析框架、判断依据、横向洞察”做出来。
- 下一步最优先的不是继续补文案，而是先重构页面叙事，再补来源证据链。

3. 再补详情页里的“判断依据”和“样本角色”。
