# AI 竞品联网调研执行模板

## 一、文档目的

这份文档用于指导 AI 竞品分析项目的联网调研工作，目标不是简单搜集资料，而是产出一份：

- 可追溯
- 可比较
- 可解释
- 可支撑分析结论

的研究底稿。

适用场景：

- AI 产品竞品分析
- 面试作品集准备
- 产品研究报告整理
- 页面内容更新与校对

---

## 二、调研目标

联网调研前，先明确这次调研要回答哪些问题。针对当前项目，统一聚焦以下 4 个核心问题：

1. 这个产品服务谁，它的核心定位是什么
2. 它的关键体验路径是如何设计的
3. 它的能力边界在哪里，强项和短板分别是什么
4. 它如何收费，以及如何承接团队或企业场景

这 4 个问题对应后续页面里的分析框架：

- 产品定位
- 体验设计
- 能力边界
- 商业化路径

所有调研内容都应尽量映射到这四个维度中，避免搜到很多信息但无法进入分析框架。

---

## 三、调研样本范围

当前首批建议调研样本：

- ChatGPT
- Gemini
- Claude
- Perplexity
- Cursor
- GitHub Copilot
- Kimi
- 豆包

样本纳入标准建议统一为：

1. 在对应赛道中具有代表性
2. 用户认知度较高，适合作为面试交流样本
3. 产品形态存在明显差异，能形成比较价值
4. 能获取到足够公开资料
5. 近一年仍在持续更新

如果后续增加样本，也要继续满足以上标准，避免产品列表变成无边界堆积。

---

## 四、信息来源分级

联网调研必须控制来源质量，不能把所有信息混在一起使用。

### 4.1 一级来源：核心依据

优先使用以下来源作为事实依据：

- 官方官网首页
- 官方产品介绍页
- 官方定价页
- 官方帮助中心 / 文档
- 官方博客 / 官方更新日志
- 官方发布会页面

适合承载的信息：

- 产品定位
- 核心功能
- 定价结构
- 团队版 / 企业版能力
- 最新产品方向

### 4.2 二级来源：补充验证

可以作为补充背景，但不建议单独支撑核心结论：

- 主流科技媒体报道
- 官方负责人公开访谈
- 官方社交媒体公告
- 权威行业研究内容

适合承载的信息：

- 市场背景
- 产品节奏
- 对外叙事变化
- 外部评价补充

### 4.3 三级来源：体验补充

只能用于补充观察，不作为唯一证据：

- 用户社区讨论
- 第三方测评
- 视频演示
- 社交平台体验反馈

适合承载的信息：

- 用户真实使用感受
- 常见问题
- 体验偏好
- 争议点

### 4.4 来源使用原则

- 核心判断优先使用一级来源
- 二级来源用于交叉验证和补上下文
- 三级来源只能作为参考，不单独形成关键结论
- 所有带时间属性的信息都应记录调研日期

## 五、单个产品的标准调研顺序

每个产品都按相同路径调研，保证可比性。

### 第一步：看官网首页

目标：

- 判断产品最先强调的核心价值
- 判断其对外定位
- 初步识别目标用户

重点记录：

- 首页主标题
- 一句话卖点
- 核心入口形式
- 首屏强调的能力

要回答的问题：

- 它最想被用户记住成什么产品
- 它首先解决的是什么问题

### 第二步：看功能页 / 产品介绍页

目标：

- 明确官方主推能力
- 确认关键场景
- 判断产品体验重心

重点记录：

- 支持哪些核心能力
- 是否支持多模态
- 是否支持搜索 / 文件 / 长文本 / 编程 / Agent
- 是否强调协作、组织或系统集成

要回答的问题：

- 它最强的能力是什么
- 它的主工作流如何被组织起来

### 第三步：看定价页

目标：

- 判断商业化路径
- 区分个人版、团队版、企业版

重点记录：

- 免费版和付费版区别
- 个人付费门槛
- 团队 / 企业能力
- API、席位、配额或高级能力限制

要回答的问题：

- 它靠谁付费
- 它如何从个人用户延展到组织用户

### 第四步：看帮助中心 / 文档

目标：

- 识别真实能力边界
- 找到官网首页不会强调的限制条件

重点记录：

- 是否支持文件上传
- 是否支持联网
- 是否支持工具调用
- 是否支持团队管理
- 是否支持权限、安全、合规能力

要回答的问题：

- 它能做什么
- 它不能稳定做什么
- 它在哪些任务上存在明显边界

### 第五步：看最近更新

目标：

- 确认产品当前发展方向
- 避免结论过时

重点记录：

- 最近 3 到 6 个月的重要更新
- 最新强调的能力变化
- 定位是否发生迁移

要回答的问题：

- 这个产品最近在强化什么
- 旧印象是否已经失效

## 七、如何把调研信息写成分析结论

竞品分析最忌讳“只有描述，没有判断”。  
因此每个关键结论建议统一写成：

```text
判断 + 依据 + 影响
```

示例：

- 判断：Perplexity 更像研究入口，而不是通用助手替代品
- 依据：官网叙事、搜索式交互、引用机制和结果结构都围绕检索与资料整合展开
- 影响：它在事实核查和资料收集场景更强，但在复杂创作闭环上不占优

再例如：

- 判断：Cursor 的核心竞争力不在聊天能力，而在真实工程闭环
- 依据：官方产品叙事、IDE 深度集成、代码库理解和任务执行路径都围绕开发工作流展开
- 影响：它适合作为编程 Agent 样本，但不适合作为通用助手样本理解

这一步是整个调研里最能体现竞品分析能力的部分。

## 八、如何映射到四维分析框架

所有联网调研内容最终都要收敛到统一框架中。

### 8.1 产品定位

关注问题：

- 它服务谁
- 它解决什么高频问题
- 它的主战场在哪里
- 它和同类产品最本质的区别是什么

输出方式建议：

- 通用入口型
- 研究检索型
- 编程闭环型
- 中文资料处理型
- 生态承接型

### 8.2 体验设计

关注问题：

- 用户如何进入产品
- 关键任务路径长不长
- 产品如何降低上手门槛
- 是对话式、搜索式、IDE 式还是文档式

输出方式建议：

- 低门槛对话式
- 搜索结果组织式
- IDE 协作式
- 文档处理导向式

### 8.3 能力边界

关注问题：

- 哪些能力是强项
- 哪些能力只是覆盖但不稳定
- 哪些场景根本不是重点

输出方式建议：

- 强研究弱创作
- 强编码弱通用
- 强多模态弱企业承接
- 强中文资料处理弱工程闭环

### 8.4 商业化路径

关注问题：

- 免费与付费如何区分
- 核心收费对象是谁
- 是否支持团队与企业扩展
- 是否依托平台生态承接价值

输出方式建议：

- 个人订阅驱动
- 团队协作驱动
- 企业承接驱动
- 平台生态驱动

## 九、研究底稿与页面展示的关系

联网调研完成后，建议产出两层内容。

### 9.1 研究底稿

给自己和后续维护使用，要求：

- 信息完整
- 来源保留
- 时间可追溯
- 结论有依据

### 9.2 页面展示稿

给面试或展示使用，要求：

- 信息压缩
- 对比清晰
- 判断明确
- 结构统一

页面不是研究全过程的原样展示，而是研究结果的高效表达。

## 十、建议的实际执行流程

### 第一阶段：搭模板

先完成：

1. 统一字段
2. 统一来源口径
3. 统一判断写法

### 第二阶段：逐个产品调研

按相同路径完成：

1. 官网首页
2. 功能页
3. 定价页
4. 文档页
5. 更新页

### 第三阶段：沉淀四维分析

把事实信息收束成：

- 产品定位判断
- 体验设计判断
- 能力边界判断
- 商业化路径判断

### 第四阶段：提炼横向洞察

基于全部样本沉淀 3 到 5 条跨产品结论，例如：

- 通用助手赛道竞争焦点正在从模型能力转向工作流承接能力
- AI 搜索产品的核心价值在于降低信息获取和核查成本
- 编程 Agent 的关键差异在于是否进入真实工程闭环

### 第五阶段：回填页面

将调研结果映射到：

- 首页关键洞察
- 对比矩阵
- 产品详情页
- 来源与更新时间区块

## 十一、调研过程中的注意事项

### 1. 不要把“事实”和“判断”混写

例如：

- 事实：官网提供 Team / Enterprise 套餐
- 判断：该产品具备明确的组织级承接路径

### 2. 不要只看首页就下结论

很多产品首页叙事和真实能力边界并不完全一致，必须结合定价页和文档页判断。

### 3. 不要把功能覆盖等同于能力优势

例如“支持文件上传”不代表“文档处理能力强”，还要看工作流设计和结果稳定性。

### 4. 不要为了凑整齐而做虚假精确判断

如果某项能力缺少充分证据，可以先标记为“待确认”，不要硬写强弱。

### 5. 所有可能变化的信息都要记录日期

尤其包括：

- 定价
- 套餐结构
- 功能开放范围
- 企业能力
- 新发布能力

---

## 十二、最终交付建议

完成一轮联网调研后，建议至少沉淀以下成果：

1. 每个产品一份研究卡
2. 一份横向对比矩阵
3. 一份关键洞察总结
4. 一份来源链接清单
5. 一份更新时间记录

如果用于面试作品，建议最终呈现逻辑为：

1. 为什么选这些样本
2. 我用什么框架分析
3. 我得出了哪些横向判断
4. 每个判断的依据是什么

---

## 十三、结论

对于这个项目，联网调研的核心不是“找到更多资料”，而是建立一套：

- 有样本边界
- 有来源分级
- 有统一字段
- 有分析框架
- 有证据支撑

的研究流程。

只要这套流程跑通，后续不管是继续补产品、改页面，还是用于面试表达，都会更稳。
